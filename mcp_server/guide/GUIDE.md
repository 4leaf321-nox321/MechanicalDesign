# Mechanical Design — 사용 안내

기계설계 계산을 **카드** 단위로 만들어 두고, 사람이 입력값만 바꿔 가며 쓰는
시스템입니다. 이 안내는 서버가 쥐고 있으므로 항상 최신입니다.

---

## 0. 먼저 알아야 할 것 — 저장과 계산은 다르다

서버는 수식을 **글자로 저장할 뿐** 말이 되는지 보지 않습니다. 없는 기호를
참조하거나 서로를 참조해 영영 풀리지 않는 정의도 그대로 저장되고, 201 을
돌려받습니다.

사람이 화면에서 만들 때는 만든 사람이 바로 계산 버튼을 눌러 확인합니다.
여기서는 그 확인이 없습니다. 그래서 **카드를 만들거나 고친 뒤에는 반드시
`validate_card()` 를 부르세요.** 이것이 이 안내에서 가장 중요한 한 줄입니다.

`ok: true` 는 문제가 없고 **시험 계산까지 실제로 돌았을 때만** 나옵니다.
`trial_skipped` 에 사유가 들어 있으면 계산은 안 돌아 본 것이니, 그때의 통과는
통과가 아닙니다(서버에 Node.js 가 없는 경우입니다 — 사람에게 알려 주세요).

---

## 0.5. 당신이 만든 카드는 초안이다

여기서 만든 카드는 **당신과 관리자에게만 보입니다.** 다른 사람의 목록에는
나타나지 않고, 사람이 웹에서 열어 **게시** 를 눌러야 모두가 쓸 수 있게 됩니다.

게시는 도구로 할 수 없습니다. 일부러 그렇게 두었습니다.

검증이 보는 것은 "계산이 도는가" 이지 "공학적으로 맞는가" 가 아닙니다. 단위가
어긋났거나(mm 와 m), 계수를 잘못 골랐거나, 안전율을 빠뜨려도 계산은 멀쩡히
돕니다. 이 카드로 사람이 설계 판단을 하게 되므로, 그 사이에 사람 한 명이
반드시 있어야 합니다.

**그러니 다 만들었으면 사람에게 넘기세요.**

1. `validate_card()` 로 대표적인 입력값을 넣어 돌립니다
2. `save_record()` 로 그 계산을 **기록으로 남깁니다.** 말로만 전한 숫자는
   대화가 끝나면 사라지지만, 기록은 사람이 나중에 열어 그때 값을 그대로
   다시 볼 수 있고 계산서로 인쇄할 수도 있습니다
3. 나온 **숫자를 그대로 보여 줍니다** — "응력 20 MPa, 최대 길이 9 mm" 처럼
4. 크기가 상식적인지 확인하고 웹에서 게시해 달라고 합니다

"카드를 만들었습니다" 로 끝내면 안 됩니다. 그 카드는 아직 아무에게도 안 보이고,
사람은 목록에서 찾다가 맙니다.

`list_my_drafts()` 로 아직 안 넘긴 것이 있는지 볼 수 있습니다.

### 이미 게시된 카드를 고칠 때

고칠 수는 있습니다. 다만 **당신이 손댔다는 사실이 카드에 남습니다** — 게시한
뒤에 기계가 또 고치면 화면에 "게시 후 AI 수정됨" 이 붉게 뜹니다. 그 사람이
확인하고 게시한 것은 지금 내용과 다른 카드이기 때문입니다.

그러니 이미 쓰이고 있는 카드를 고칠 때는 **먼저 사람에게 말하세요.** 사람이
잠깐 내려 주면(초안으로 되돌리기) 고친 뒤 다시 확인하고 올릴 수 있습니다.
말없이 고쳐 놓으면, 그 카드로 계산하던 사람이 어제와 다른 숫자를 보게 됩니다.

무엇을 고쳤는지는 카드의 **변경 이력**에 그대로 남습니다 —
`응력(sig) — 수식: F / A → F / A * 1.5` 처럼. 사람이 그 자리에서 되돌릴 수도
있습니다. 그러니 고친 내용을 말로도 그대로 전하세요. 이력에 남는 것과 사람이
아는 것은 다릅니다.

## 1. 구조

```
카드 (Card)              하나의 설계 계산. 예: "볼트 강도 검토"
 ├─ 컨테이너 (Container)  화면의 구역. 계산을 묶지 않고 보이는 자리만 나눈다
 ├─ 변수 (Variable)       입력값·중간값·결과값
 └─ 이미지 (Image)        도면·그림
```

**컨테이너는 계산 단위가 아닙니다.** 계산은 카드 전체에서 한 번에 돌기 때문에,
어느 컨테이너에 놓였는지는 값에 아무 영향이 없습니다. 같은 변수를 두 컨테이너에
함께 보여 줄 수도 있습니다 — 값은 하나이고 보이는 자리만 늘어납니다.

변수를 컨테이너에 놓지 않아도 계산은 됩니다. 화면에 안 보일 뿐입니다.

---

## 2. 변수 — 계산 순서가 곧 규칙이다

계산은 **입력값 → 중간값 → 결과값** 순서로 한 번 돕니다.

| category | 뜻 | var_type |
|---|---|---|
| `input` | 사람이 넣는 값 | `slider` `text` `dropdown` `array` |
| `intermediate` | 중간 계산 | `formula` `table` `conditional` `interp_table` |
| `output` | 최종 결과 | `formula` `table` `conditional` `interp_table` |

여기서 **가장 자주 틀리는 것**:

> **중간값은 결과값을 참조할 수 없습니다.**

결과값은 중간값보다 나중에 계산되므로, 중간값이 결과값의 기호를 부르면 그때는
아직 값이 없습니다. 그러면 `알 수 없는 이름: sig` 라는 오류가 나오는데, 기호는
분명히 있으므로 오타를 찾다가 시간을 버리게 됩니다. `validate_card()` 가 이
경우를 따로 짚어 줍니다.

중간값끼리는 **순서에 상관없이** 서로 참조해도 됩니다. 계산기가 풀릴 때까지
반복하며 스스로 순서를 찾습니다. 다만 서로를 참조하면(A→B→A) 영영 풀리지
않으므로 순환 참조로 걸립니다.

### symbol

수식에서 이 변수를 부르는 이름입니다. 비워 두면 **다른 수식에서 쓸 수 없습니다.**
계산에 쓰일 변수라면 반드시 채우세요.

기호를 바꾸면 그 기호를 쓰던 다른 수식들이 **서버에서 함께 바뀝니다.** 손으로
따라 고치지 마세요 — 두 번 바뀝니다.

## 3. 수식

사칙연산과 괄호, 그리고 아래 함수를 씁니다. 거듭제곱은 `^` 또는 `**`.

**숫자**
`sin` `cos` `tan` `asin` `acos` `atan` `atan2(y,x)`
`radians(deg)` `degrees(rad)` `pi()` `abs` `sqrt` `log` `log10` `exp` `pow(b,e)`
`prob(value, mean, stdev)` — 정규분포 누적 확률(%)

이 함수들은 **배열을 주면 원소마다 걸리고 결과도 배열**입니다.
`sin(radians(A))` 는 A 의 각 각도에 sin 을 건 배열입니다.

**집계 — 배열을 값 하나로 줄인다**
`min` `max` `average` `sum` `count` `size`

**원소별 — 결과가 다시 배열이다**
`add(a,b)` `sub(a,b)` `mul(a,b)` `div(a,b)`

**배열 만들기·꺼내기**
`range(start, end, step=1)` → `range(1,5)` = [1,2,3,4,5]
`at(list, n)` — n 번째 원소. **1부터 셉니다**(화면이 "열 1" 처럼 1부터 세므로)

**문자열**
따옴표로 쓰고 `+` 로 잇습니다: `"응력 " + sig + " MPa"`

### 배열에 주의할 점

배열끼리 `+` 로 더하면 **오류가 납니다.** 자바스크립트라면 `[1,2]+[3,4]` 가
`"1,23,4"` 라는 문자열이 되어 조용히 틀린 답이 나오는데, 그 결과가 그럴듯해서
아무도 알아채지 못합니다. 그래서 막아 두었습니다 — 원소별로 더하려면
`add(A, B)` 를 쓰세요.

## 4. 계산 변수의 정의 형태

`formula` 말고는 JSON 을 넘깁니다. 도구는 dict 를 받아 알아서 직렬화합니다.

### table — 표에서 값 찾기

```json
{
  "lookup_mode": "row",
  "columns": ["재질", "항복강도", "인장강도"],
  "rows": [["SS400", "245", "400"], ["SM45C", "343", "569"]],
  "result_column_index": 1,
  "keys": [{"column_index": 0, "expression": "mat", "match_mode": "exact"}]
}
```

- `lookup_mode`: `row`(가로로 찾기, 기본) / `column`(세로) / `cell`(행·열 교차)
- `match_mode`: `exact` `nearest` `floor` `ceiling` `interpolate` `range`
- `keys[].expression` 은 **수식**입니다 — 다른 변수의 기호를 쓸 수 있습니다

표를 여러 카드에서 함께 쓸 거라면 **베껴 넣지 말고** 표 정의를 참조하세요.
`list_table_templates()` 로 이미 있는 것을 먼저 보세요. 베껴 넣으면 원본이 바뀌었을
때 어느 카드가 옛 값을 쓰는지 알 수 없게 됩니다.

### conditional — 조건에 따라 다른 수식

```json
{
  "branches": [
    {"condition": "sig > 200", "formula": "\"불합격\""},
    {"condition": "sig > 150", "formula": "\"주의\""}
  ],
  "default_formula": "\"합격\""
}
```

위에서부터 보고 처음 맞는 것을 씁니다. 아무것도 안 맞으면 `default_formula`.
**`default_formula` 를 비워 두지 마세요** — 안 맞으면 값이 없는 채로 끝납니다.

### interp_table — 두 열 사이 선형 보간

```json
{
  "columns": ["온도", "허용응력"],
  "rows": [["20", "120"], ["100", "105"], ["200", "88"]],
  "x_column_index": 0,
  "y_column_index": 1,
  "x_expression": "T"
}
```

범위를 벗어나면 양 끝 두 점으로 **외삽**합니다(오류가 아닙니다). 물성값이라면
그 외삽이 물리적으로 말이 되는지 사람에게 확인받으세요.

### dropdown 입력

`options=["SS400", "SM45C"]` 처럼 리스트로 넘깁니다.

### array 입력

`var_type="array"`. 값은 숫자 배열이며, `sum` `average` 같은 집계나
`add` `mul` 같은 원소별 함수로 다룹니다.

## 5. 권장 절차

1. `get_guide()` — 지금 읽고 있는 것
2. `list_cards()` / `get_card(id)` — 이미 있는 것을 먼저 봅니다.
   비슷한 카드가 있으면 그 짜임새를 따르는 편이 사람에게 익숙합니다
3. `list_table_templates()` — 쓸 표가 이미 있는지
4. `create_card(name, description)`
5. `create_variable(...)` — **입력값부터** 만드세요. 중간값·결과값이 참조할
   기호가 먼저 있어야 검증이 깔끔합니다
6. `create_container(...)` + `set_widget_layout(...)` — 화면 배치
7. **`validate_card(card_id, values={...})`** — 대표적인 입력값을 넣어 실제
   숫자가 나오는지 봅니다. `issues` 가 비고 `ok: true` 여야 끝난 것입니다
7-1. `save_record(card_id, title, values)` — 그 계산을 기록으로 남깁니다.
   `list_records()` 로 같은 계산을 이미 누가 해 두었는지 미리 볼 수도 있습니다
8. 사람에게 **결과 숫자를 보여 주고**, 웹에서 확인해 **게시** 해 달라고 하세요
   (0.5장). 게시 전까지 그 카드는 다른 사람에게 보이지 않습니다

### 8번을 건너뛰지 마세요 — 여기서 끝내면 아무 일도 일어나지 않습니다

검증이 통과했다는 것은 "계산이 돈다" 는 뜻이지 "공학적으로 맞다" 는 뜻이
아닙니다. 계수를 잘못 골랐거나 안전율을 빠뜨려도 계산은 멀쩡히 돕니다. 이
카드로 사람이 설계 판단을 하게 되므로, 나온 숫자가 상식적인 크기인지 반드시
사람의 눈을 거치게 하세요.

### 단위는 꼭 채우세요

`unit` 을 채우면 검증이 **단위끼리 맞는지도 봅니다.** 안 채우면 그 검사는
통째로 건너뜁니다 — 빈 칸은 "무차원" 이 아니라 "안 적었다" 로 봅니다.

특히 잡아 주는 것이 **배율 어긋남**입니다. `F[N] / A[mm2]` 는 MPa 인데 단위를
Pa 라고 적으면 값이 100만 배 어긋납니다. 차원은 맞아서 계산은 멀쩡히 돌고
숫자도 그럴듯해서, 이것만은 사람도 잘 못 잡습니다.

적는 법: `mm` `mm2` `N/mm2` `kg*m/s2` `1/s` `deg` `%`. 무차원이라고 **말하고
싶으면** `-` 로 적으세요. 못 읽는 단위(오타 `Mpa` 같은)는 검증이 알려 줍니다.

이 검사는 **경고일 뿐 아무것도 막지 않습니다.** 그래서 더 눈여겨보세요 —
막히는 오류는 화면이 비어서 금방 알지만, 단위가 틀린 값은 그대로 설계에 들어갑니다.

단위를 채워 두면 사람이 값을 넣을 때 **다른 단위로 넣고 자동 환산**할 수도
있습니다(N 으로 선언된 칸에 kN 으로 입력). 그러니 단위는 검사를 위해서만이
아니라 쓰는 사람을 위해서도 채우는 편이 낫습니다.

## 6. 자주 만나는 오류

| 메시지 | 뜻 |
|---|---|
| `'X' 를 찾을 수 없습니다` | 그 기호의 변수가 없거나, 변수에 기호를 안 넣었습니다 |
| `'X' 는 결과값이라 중간값에서 쓸 수 없습니다` | 단계 역참조. 2장을 보세요 |
| `순환 참조입니다` | 두 변수가 서로를 참조합니다 |
| `기호 'X' 가 '...' 와 겹칩니다` | 같은 기호를 두 변수가 씁니다 |
| `'sqrt' 는 내장 함수 이름이라...` | 함수 이름을 기호로 쓸 수 없습니다 |
| `배열끼리는 + 로 더할 수 없습니다` | `add(A, B)` 를 쓰세요 |
| `단위는 ... 인데 수식이 내는 값은 ... 배입니다` | 배율 어긋남. 100만 배 틀린 값이 그대로 나옵니다 |
| `단위 '...' 를 읽지 못했습니다` | 오타이거나 등록되지 않은 단위입니다 |
| `토큰이 유효하지 않거나...` | 앱의 "내 액세스 토큰" 화면에서 새로 발급하세요 |

## 7. 권한과 흔적

이 MCP 는 **토큰 주인의 권한으로만** 동작합니다. 만들어진 카드는 그 사람이
만든 것으로 남습니다. 할 수 없는 일이 있다면 토큰이 부족한 것이 아니라 그
계정의 권한이 그런 것이니, 사람에게 알려 주세요.

**당신이 한 일은 카드에 남습니다.** 당신이 만든 카드에는 "AI 작성" 이 붙고,
사람이 만든 카드를 고쳤으면 고친 시각이 남습니다. 감추려고 만든 것이 아니라,
나중에 그 계산이 이상하다는 얘기가 나왔을 때 **어디를 먼저 볼지**를 알기
위해서입니다. 게시된 카드는 사람이 짠 것이나 AI 가 짠 것이나 똑같이 생겼습니다.
